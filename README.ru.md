# Planner

[English](README.md) · [Русский](README.ru.md)

[![Проверки](https://github.com/realfamousbae/planner/actions/workflows/checks.yml/badge.svg)](https://github.com/realfamousbae/planner/actions/workflows/checks.yml)

**Продумать изменения. Передать план. Реализовать в новой сессии.**

Planner — переносимый Agent Skill для Codex, Claude Code и совместимых агентов.
В первой сессии агент изучает репозиторий, обсуждает решения и готовит план.
Во второй другая модель выполняет этот план и обновляет прогресс.
Весь контекст задачи хранится в одном `PLANNER.md` в корне репозитория.

Стартовый профиль — **Sol / high → Terra / medium**. Его можно изменить.
Если эти модели недоступны, скилл предлагает аналоги и согласует выбор.
Экономия и качество пока не измерены сравнительными испытаниями.

## Установка

Нужен Python 3.9+ для установщика. Сам скилл состоит из Markdown и YAML,
не требует API-ключей и не запускает модели самостоятельно.

```sh
git clone https://github.com/realfamousbae/planner.git
cd planner
python3 scripts/install.py --dry-run
python3 scripts/install.py
```

Установщик определяет доступные `codex` и `claude` по PATH и создаёт копии:

| Агент | Каталог |
| --- | --- |
| Codex | `~/.agents/skills/planner` |
| Claude Code | `~/.claude/skills/planner` |

Можно выбрать `--agent codex`, `--agent claude` или `--agent both`.
Существующие установки не перезаписываются. Чтобы обновить скилл, сначала
проверьте старую копию, удалите или перенесите её и установите новую.
Изменения этого репозитория не обновляют установленные копии автоматически.

После установки откройте новую сессию и проверьте наличие Planner в списке
скиллов. Не устанавливайте дубли одновременно в пользовательский и проектный
каталоги. Установка только в проект описана в [английском README](README.md#install).

## 1. Планирование

Выберите модель для планирования, включите **встроенный Plan Mode** и отправьте:

```text
# Codex
$planner plan Добавить пагинацию в ленту активности.

# Claude Code
/planner plan Добавить пагинацию в ленту активности.
```

Скилл спросит effort (по умолчанию high), изучит код и задаст вопросы.
Затем предложит план и модель для реализации. Утвердите итоговую версию,
выйдите из Plan Mode и в той же сессии отправьте:

```text
Сохрани утверждённый план в PLANNER.md. Реализацию не начинай.
```

Пока режим запрещает запись, план остаётся в переписке. Скилл должен
подтвердить сохранение файла перед передачей задачи в новую сессию.
Если у агента нет встроенного Plan Mode, планирование не запускается.

## 2. Реализация

Откройте новую сессию в том же репозитории/worktree, выберите рекомендованную
модель и отключите Plan Mode:

```text
# Codex
$planner implement

# Claude Code
/planner implement
```

Дополнительные инструкции можно дописать после режима:

```text
$planner implement Используй high effort. Сохрани совместимость существующего API.
```

Агент прочитает план, согласует effort и проверит актуальность относительно
кода. При отсутствии доступного управления настройками попросит переключить
их вручную. Он не выдаёт выбранные настройки за подтверждённые и не меняет
глобальные предпочтения.

Технические детали агент решает самостоятельно. Изменения цели, архитектуры,
публичных интерфейсов и объёма обсуждает с пользователем. Этапы, реальные
результаты проверок и следующий шаг записывает в `PLANNER.md`.
После прерывания можно открыть ещё одну сессию с `implement`.

Один файл хранит одну задачу. Незавершённая задача не заменяется без обсуждения;
завершённый план заменяется после утверждения следующего. Архивов нет.
Инструкции скилла написаны на английском, а общение и планы следуют языку пользователя.
